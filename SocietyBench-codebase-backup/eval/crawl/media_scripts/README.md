# media_scripts — social-media validity check (v1 keywords / v2 kimi, generic for all events)

> Media validation = filtering the raw social-media DB (media_crawler.db, all posts + comments) down to a valid CSV of records "related to the target event".
> Companion SKILL: [../../skills/media-crawl/step4-validate/SKILL.md](../../skills/media-crawl/step4-validate/SKILL.md).

## Standard = v2 (kimi semantic); v1 kept as baseline/control

| Script | Method | Reuse | Status |
|---|---|---|---|
| **`export_llm_validated_v2.py`** | **kimi judges semantic relevance per post** (one step, DMXAPI kimi-k2.5) | `--topic "<one-line event>"` | **media standard** |
| `export_llm_validated_v1.py` | **LLM-generated layered keyword table → layered matching**: kimi generates anchor/entity/event/noise from the topic; valid = no noise hit AND ( any **anchor** hit (strong proper noun, alone suffices) OR (**entity AND event** co-occur) ) | `--topic "<event>"` (automatic) or manual `--keywords-config` | kept: fast, lean baseline |

Both are **generic and reusable, zero hard-coded keywords, adaptive to 5–7 platforms, read db → write valid CSV**; only the decision layer differs.

## Measured comparison (SMCI, 174,779 raw)
| Method | Posts | Comments | Total | Notes |
|---|---|---|---|---|
| v2 kimi (standard) | 247 | 2,197 | **2,444** | per-post semantic judgment; good recall and precision |
| v1 layered keyword table (LLM-generated anchor/entity/event/noise) | 102 | 1,351 | **1,453** | after tuning: proper-noun solo hit + entity∧event co-occurrence; 1 LLM call, runs in seconds |
| v1 legacy (flat keyword OR, untuned) | 675 | 4,980 | 5,655 | ✗ keyword list contained broad terms (e.g. "AI server" / company nickname) → over-recall; retired |
| v1-SMCI triple AND (outlier) | 21 | 36 | 57 | too strict, kills valid data; **not a template** |

→ Keyword OR is too loose, triple AND too strict; **kimi semantic sits in between**, hence the standard.

## Legacy scripts (event-specific instances, kept for reference, not templates)
| File | Description |
|---|---|
| `export_llm_validated.smci.py` | SMCI's **entity∧subject∧action triple AND** — **outlier, too strict** (only this event was written this way); kept as a counterexample |
| `export_llm_validated.wuda.py` | Wuhan University instance (keyword OR + per-source constraints) |
| `validate_posts.template.py` | step4-validate three-layer funnel rule template (tiktok source) |
| `llm_validate_creator_posts.py` | creator-mode LLM re-check (migrated to DMX: BASE_URL=DMX, MODEL=kimi-k2.5, key read from `DMXAPI_KEY` env, 2026-07-01) |

> Note: media validation methods were **not uniform** across historical events — US-Iran / TikTok / tariff used keyword OR (45.7% / 99.9% / 77%), only SMCI used triple AND (0.03%). The v1 template generalizes the real "keyword OR" practice; v2 uniformly replaces it with kimi.

## Usage
```bash
# v2 (standard, kimi semantic)
PYTHONPATH=<repo>/code/eval python3 export_llm_validated_v2.py \
    --db media_crawler.db --topic "<one-line event>" --output data/valid_data_llm_verified_v2.csv

# v1 (keyword-OR baseline; keywords auto-generated by kimi from the topic)
PYTHONPATH=<repo>/code/eval python3 export_llm_validated_v1.py \
    --db media_crawler.db --topic "<one-line event>" --output data/valid_data_llm_verified_v1.csv
#   -> kimi generates the layered keyword table {anchor_terms, entity_terms, event_terms, noise_patterns},
#      saved to generated_keywords.json (reproducible / manually tunable)
#   valid = no noise hit AND ( any anchor hit OR (entity hit AND event hit) )
#   manual override: --keywords-config event_keywords.json; legacy flat {"keywords":[...]} accepted (treated as anchors)
```
